§1このスキルの役割

既存スライドの共通シェルを調査し、新しい型を登録・検証・公開する。単発のスライド生成は既存の生成スキルへ委譲する。

対象
参考画像、既存HTML、蓄積簿、カタログ生成処理
判断
既存型の派生か、再利用可能な新型かを確定する

§2出力

このスキルが作るのは、単発HTMLではなく再利用可能な型登録一式です。

型登録一式
共通シェルに準拠したサンプルHTML、サムネイル、カタログ登録、公開確認結果。

§3既存型との判定

全スライドを走査し、実表示HTMLとリダイレクト用HTMLを分ける。ヘッダーだけでなく、背景・寸法・縮小式・フッターまで比較する。

全件走査 → 共通シェル比較 → 例外分類 → 新型／派生型を決定

§4共通シェル契約

項目契約
外枠`.slide-viewport` + `.slide`、1280×720
見出し`.slide-header` + `.slide-title`
末尾`footer.slide-meta`
表示縮小処理、モバイル横スクロールなし

§5生成と登録

  1. 生成スキルでサンプルHTMLを作る
  2. 蓄積簿と型許可一覧へ登録する
  3. node scripts/build-catalog.mjsで一覧を生成する
  4. サムネイルを公開用スライドフォルダへ置く
  5. スライドをコミット後、一覧を再生成する

§6レビューと実機検証

レビュー時点は既存のHTML成果物レビューと揃える。加えて1280×720と375×667で、共通シェル・横スクロール・サムネイルの判別性を確認する。

検証用スクリーンショットは agent-home の Playwright保存先へ置き、公開用サムネイルとは分離する。

§7公開反映

push後に一覧、個別HTML、サムネイルをHTTP確認する。ローカルで存在するだけでは公開済みと判定しない。

更新順
スライドのコミット後にカタログを再生成し、`updated`を同期する

§8保存先の分離

用途保存先
検証画像・trace~/agent-home/tools/MCP/playwright/
公開サムネイルslides/<key>/サムネイル.png

§9予想を裏切る挙動

HTMLと画像がローカルにあっても、一覧生成とPagesデプロイが終わるまで公開一覧には現れない。同日更新の項目は登録順のタイブレークになる。

§10完了条件

型定義、HTML、サムネイル、蓄積簿、カタログ、レビュー、モバイル検証、公開URL確認がそろって初めて完了とする。

PASS: 公開URLで一覧・本体・サムネイルが一致

docs / project-portal — 役割分担

docsとプロジェクトポータルの構成 — 大元と閲覧を分離する

AIが読む大元はdocs/へ、人間が閲覧するHTMLはproject-portal/へ、各AIツールは索引で大元に到達する

領域役割置くもの
docs/AI可読資産の大元（英語の機械安定パス）
AIが直接読むMarkdownと根拠画像。許可する直下は rules/ と screens/ のみ プロジェクト規約の大元と、画面単位の設計資産
project-portal/人間向けHTML（日本語の分類名・ページ名）
大元または抽出結果からレンダリングした閲覧用サイト。docs/配下には置かない 規約・設計書・一覧・マトリクス等をカードで俯瞰
CLAUDE.md / AGENTS.md大元への索引（派生アダプター）
各AIツールが大元へ到達するための入口。規約本文は記載しない ツールごとの読み込み経路を固定
PROJECT TREE

AI駆動でのコンテキスト配置像

project/
├── docs/
│   ├── rules/
│   │   └── …/rule.md
│   └── screens/
│       └── screen-<id>/
├── project-portal/
│   ├── index.html
│   ├── 基盤情報/
│   ├── 規約/
│   ├── 一覧/
│   └── 画面/
├── CLAUDE.md
├── AGENTS.md
└── src/ （既存コード）
分離の原則 大元はdocs/、表示はproject-portal/ — 日本語表示は大元のメタデータから生成し、二重管理しない 1 / 3
docs / project-portal — docsの中身

docsに置くのは、規約と画面ごとの設計書

AIが読む設計資産の大元 — 分野別のルールと、1画面1フォルダの設計書で構成する

規約 docs/rules/

分野ごとのフォルダにルール文書（rule.md）を1つ。作業対象に応じて、必要な分野だけをAIへ渡せる。

命名規則・ファイル配置naming/ ・ placement/
アーキテクチャ・コーディングarchitecture/ ・ coding/
テスト・レビュー観点testing/ ・ review/
安全な操作・セキュリティ・Git運用 ほか全20分野safety/ ・ security/ ・ git/ …
画面ごとの設計書 docs/screens/

1画面＝1フォルダ（screen-画面ID）。AIが画面単位で設計・テストの文脈をまとめて読み込める。

画面基本設計書画面の目的・項目・遷移basic-design/
画面詳細設計書処理仕様と実画面の画像detailed-design/
テスト仕様書単体・結合・操作シナリオtest-specifications/
処理シーケンス画面内の処理の流れsequence-data.json
画面の台帳整備済み画面の一覧reverse-screen-registry.yml
整備の視点 AIに渡す前提で置く — 規約は分野別に、画面の知識は1画面1フォルダに揃えるのがAI駆動の土台 2 / 3

AIエージェント品質管理

提示前レビューと自己改善の循環

成果物の分類が通す観点表を決め、指摘は受けた直後に観点表へ還元される

1

どの表を通すか

観点表はレビュー観点を列挙した規約文書、判定役はレビュー専任のAIエージェント。対象物の分類が両者を機械的に決め、「+」は両方の表を通すことを表す。

先方へ出す資料 → business-content + document 判定役: business-content-reviewer
納品物や内部の設計書 → document（+ プロジェクト固有） 判定役: document-reviewer
コード差分 → code 判定役: code-reviewer
委任先からの報告 → report 判定役: report-reviewer
2

いつ通すか（3つの場面）

判定を仰ぐ（「ご確認をお願いします」）
選択を求める（選択肢の提示）
完成を宣言する（「完成しました」）

この3つのいずれかを行う前に、分類に応じた全ての表を通していること。

3

どう守らせるか（3つの検査、通知型で作業は止めない）

選択肢を提示する直前 このセッションで判定役が走ったかを検査し、未実行なら注意を注入
応答を返す直前 完成宣言や判定依頼の文言があるのに判定役が未実行なら通知
応答を返す直前 直前の発話が指摘なのに観点表が未更新なら通知

検査は場面と1対1ではなく、機械で観測できるタイミングに置く。定型句で拾えない検知漏れは、常時読み込まれる行動規範が受け持つ。

4

いつ自己改善されるか（指摘が観点へ還る経路）

入口ユーザー判定で否が出たとき
入口実測で自分の誤りを見つけたとき
指摘 → 観点として言語化 → 観点表へ追記（機械で拾えるものは検査へ） → 既存成果物を全件見直す → 次の成果物へ

還元は指摘を受けたその場で行い、先送りしない。作業手順の誤りは観点表ではなく規約の「繰り返した失敗」へ記録する。

要点 欠けやすいのは観点ではなく「どの表を通すかの判定」と「通した証明」。還元された観点は次の成果物から検査を強くし、同じ指摘を2度受けない。

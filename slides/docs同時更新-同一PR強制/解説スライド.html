AI開発ガバナンス — ドキュメント鮮度

設計書はコードと同じ変更単位で更新させ、乖離を作らない

AI開発では設計書がそのままAIの入力になる — 乖離はAIの誤った前提に直結する

起きる失敗

コードだけが先に進む

実装を急ぐと設計書の更新が後回しになり、ドキュメントと実装が少しずつ乖離していく。

  • 誰も設計書を信用しなくなる
  • AIが古い設計書を読み、誤った前提で作業する
採用する運用

コードと設計書を同じPRに縛る

コード変更と対応する設計書の更新を、同じ変更提案（PR）の中で行うことを必須にする。設計書は機能 → 画面 → 操作フロー → 開発プロセスの階層で管理する。

  • 実装と文書が常に同じ鮮度を保つ
  • AIが最新の設計を前提に作業できる
強制の仕組み

同時更新は「お願い」ではなく機械照合で強制する

PRに対応する設計書更新が含まれるかを機械照合し、漏れていれば差し戻す。更新忘れが人の注意力に依存しない。

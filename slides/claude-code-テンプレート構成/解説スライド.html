CLAUDE CODE · 01

5つの設定資産は役割で置き分ける

概要・規約・手順・役割・実行制御を、読み込まれ方に合わせて分離する

資産正規配置AIへの効果
プロジェクト文脈CLAUDE.md作業の前提、用語、構成を共有する
条件付き規約.claude/rules/*.md対象パスに応じて規約を注入する
再利用手順.claude/skills/<name>/SKILL.md繰り返す作業を同じ順序で実行する
専門エージェント.claude/agents/*.md役割と利用ツールを分けて委任する
実行境界.claude/settings.json / .mcp.json権限、フック、外部ツール接続を制御する
CLAUDE CODE · 02

文脈とrulesは読込条件が異なる

CLAUDE.mdは平文、パス限定ruleはYAML frontmatterで対象を宣言する

PROJECT CONTEXT

CLAUDE.md

プレーンMarkdownでプロジェクトの共通知識を書く。
YAML frontmatterは使わない。

配置作業対象の階層に沿って置き、関連する文脈を読み込ませる。
向く内容技術構成、用語、共通コマンド、リポジトリ全体の注意事項。

PATH-SCOPED RULE

.claude/rules/*.md

---
paths:
  - "src/**"
---
# フロントエンド規約
  • pathsあり：一致するファイルを扱う時だけ読み込む。
  • pathsなし：無条件で読み込む。
  • 本文はMarkdown。適用条件と規約本文を同じファイルで完結させる。
CLAUDE CODE · 03

skillsは手順、agentsは専門役割

再現したいワークフローと、委任したい判断主体を別の資産として管理する

REUSABLE WORKFLOW

Skill

.claude/skills/deploy/
├─ SKILL.md
├─ scripts/
└─ references/

起動条件、手順、完了条件をSKILL.mdへまとめ、必要な時に呼び出す。

同じ仕事を同じ順序で再現するための「手順書」。

SPECIALIST ROLE

Custom agent

.claude/agents/reviewer.md
YAML frontmatter
model / tools

役割の説明と利用可能なモデル・ツールを定義し、専門的な調査やレビューを委任する。

  • Skillは「どう進めるか」を固定する。
  • Agentは「誰の視点で担うか」を分ける。
CLAUDE CODE · 04

実行制御は設定とMCPへ集約する

生成指示とは分離し、許可・自動処理・外部接続の境界を明示する

.claude/settings.json

permissions

allow / denyで、ツールやコマンドの実行範囲を定める。

hooks

ツール利用やセッション進行に連動する自動処理を設定する。

project settings

プロジェクト固有の実行方針を、共有可能な設定として保持する。

.mcp.json

MCP servers

外部ツールやデータソースとの接続定義をプロジェクト単位で管理する。

指示と権限を混ぜない

CLAUDE.mdとrulesは「何を守るか」を伝える。settingsとMCPは「何を実行できるか」を制御する。

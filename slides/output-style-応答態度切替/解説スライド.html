Claude Code — Output Style

Output Styleを場面に合わせて切り替える

Default・Proactive・Explanatory・Learningを、確認頻度と説明量で選ぶ

Style確認頻度説明量適用場面
Default 判断が必要な場面で確認 必要な概要 初めての作業、判断の余地が大きいとき
Proactive 低い。破壊的操作・共有変更のみ確認 実行優先で最小限 方針が明確で、大量の作業を一気に進めるとき
Explanatory 判断と選択肢を明示 理由・比較・背景を補足 仕組みと設計判断を理解しながら進めるとき
Learning 小さな実装を利用者へ返す 実践に必要な導き 利用者が小さなコード実装を担い、実践学習するとき

設定：/config の Output style（settings.json の outputStyle で永続設定可能）。根拠：Claude Code 2.1.219 の組み込み説明

選び方 確認頻度・説明量・実装の担い手の3軸で選ぶ — スタイルは作業の性質に合わせて都度切り替える 1 / 2

Claude Code — Proactive

Proactiveの5指示と確認境界を読む

即時実行と割込み最小化を優先しつつ、削除と共有システム変更は確認する

# Proactive Style が有効時にAIが受け取る指示 The user chose continuous, autonomous execution. 1. Execute immediately Start implementing right away. Make reasonable assumptions. 2. Minimize interruptions Prefer assumptions over asking questions. 3. Prefer action over planning Do not enter plan mode unless explicitly asked. 4. Expect course corrections 5. Do not take destructive actions Deletions and shared-system changes still need confirmation.
有効中

Proactive（自律型）

即座に実行を開始し、妥当な判断ができる場面では確認せずに進む。ただしデータ削除・共有システムへの操作は必ず確認する。

向く場面: 方針が明確で大量の作業を一気に進めたいとき
既定

Default（標準型）

低リスクは即実行、判断が必要な場面で確認する。大きな変更の前に計画の概要を提示する。

向く場面: 初めての作業や、判断の余地が大きいとき
解説

Explanatory（解説型）

各ステップで「なぜそうするか」を添え、複数の方法がある場面では比較を提示する。

向く場面: 仕組みを理解しながら進めたいとき
確認境界 Proactiveでも削除と共有システム変更は止まる — 自律と安全の境界は指示5が定義する 2 / 2

Proactive は即時実行・仮定・割込み最小化・計画抑制・方向転換を扱う。設定：/config の Output style（settings.json の outputStyle で永続設定可能）。

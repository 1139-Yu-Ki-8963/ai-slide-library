AI開発ガバナンス — 設定資産管理

複数AIツールの規約・スキルを一元管理する仕組み

定義は docs/ の1か所、Claude Code と Cursor はシンボリックリンクで同じファイルを読む

1

変換スクリプトによる転記

docs/rules の定義を、変換スクリプトが .claude/rules・.cursor/rules/*.mdc・AGENTS.md へその都度転記していた。

×複製がずれるため、ずれ検知・台帳・整合検査を常設していた
×変換スクリプト7本・約5,000行、規約1件の修正で4か所を触る
2

シンボリックリンクによる一元化

.claude/rules と .claude/skills は docs/ 配下へのディレクトリのリンク、.cursor/rules/*.mdc は各 rule.md へのファイルのリンクにする。

.claude/rules → docs/rules .claude/skills → docs/skills .cursor/rules/*.mdc → rule.md AGENTS.md は静的な数行のみ
レ同じ実体を指すため複製のずれが原理的に起きない
レずれ検知・台帳・変換スクリプトが0になる
3

1ファイルを両ツールが読める理由: front matter に両方の鍵を同居させる

description・globs・alwaysApply は Cursor が読み、paths は Claude Code が読む。各ツールは自分の鍵だけを見て他の鍵は無視するため、1つの rule.md がそのまま両方の設定として機能する。（注意：Cursor は 2.5 以降を使う。それより前のバージョンはリンク先を読まない不具合がある）

1

転記の限界— 複製がずれ、直すたびに4か所を触る

2

一元化— リンクで同じ実体を指し、ずれを原理的に無くす

3

両立— front matter の鍵の同居で両ツールが1ファイルを読む

導入の最初の一歩：規約1件をシンボリックリンク化し、両ツールから読めることを確認してから全件へ展開する

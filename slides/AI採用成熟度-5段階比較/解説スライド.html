AI採用成熟度モデル｜5段階比較

AI採用の5段階を、状態・機能・ガードレールで比較する

自社の現在地を確認し、次の段階へ進むために何を整備するかを判断するための全体像

このスライドの見方：段階が上がるほど「人が確認する」から「仕組みが検証する」へ移る各カードは 状態 → 使う機能 → 必要なガードレール の順
LEVEL 1

利用制限
Gated

AI利用が厳しく制限され、承認・権限・予算の枠組みが未整備。

使う機能
  • まだ本格導入しない
ガードレール
  • SSO/SCIM・役割権限
  • 組織の予算上限
  • 承認フロー

→ 導入枠組みを作る

LEVEL 2

1対1ペア作業
Assisted

1人と1エージェントが同期作業。全出力を人が確認する。

使う機能
  • Claude Code
  • Desktop / CLI / IDE
  • Analytics
ガードレール
  • 利用上限
  • 中央モデル設定
  • 利用状況監視

→ 複数運用の準備

LEVEL 3

並列運用
Parallel

1人が複数エージェントを同時運用。各作業を分離して進める。

使う機能
  • Auto mode
  • Agent view
  • Worktree isolation
  • Code / Security Review
ガードレール
  • 自動レビュー
  • E2E検証
  • 安全なコマンド

→ 出力を仕組みで検証

LEVEL 4

監督付き自律
Supervised

AIがコードの大半を書き、人は意図・例外・品質を監督する。

使う機能
  • Subagents
  • Dynamic workflows
  • Routines / batch
ガードレール
  • 自動レビュー
  • Sandbox
  • CLAUDE.md
  • モデル・トークン制御

→ 監督を仕組み化

LEVEL 5

AIネイティブ
AI-native

エージェントが起動・管理・停止まで行い、人は意図と例外を扱う。

使う機能
  • Claude Agent SDK
  • 自動応答・連携
ガードレール
  • 自動化のコスト制御
  • 用途別モデル選択
  • 例外時の停止条件

→ 安全にスケール

注意： Level 3以降は、分離・自動レビュー・E2E検証がないまま解禁しない。段階ごとのガードレールが次の段階の前提になる。
読む順序：Level 1–2で利用基盤と人の確認 → Level 3で分離・自動検証 → Level 4–5で監督とコスト制御を仕組み化

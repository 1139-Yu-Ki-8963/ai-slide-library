CODEX · 02

AGENTS.mdは階層ごとに作用する

リポジトリ上位から作業ディレクトリへ読み進み、近い階層の指示を優先する

LAYERED INSTRUCTIONS

探索は上位から現在地へ

作業対象へ至るディレクトリ階層の指示を順に読み、スコープを狭めながら具体化する。

repo/AGENTS.md
└─ packages/AGENTS.md
  └─ api/AGENTS.md

PRECEDENCE

近い指示が具体化する

1
ルートのAGENTS.md全体の規約、共通コマンド、公開安全などを共有する。
2
下位のAGENTS.md対象領域だけのテスト、命名、配置ルールを追加する。
3
AGENTS.override.md同じ階層のAGENTS.mdより優先する上書き指示として使う。
平文Markdown：指示本文はMarkdownで記述し、ファイル階層そのものを適用範囲にする。
CODEX · 03

skillsは手順、agentsは委任先

再利用ワークフローはファイル、複数エージェントの役割はconfig.tomlで宣言する

REPOSITORY SKILL

.agents/skills/

.agents/skills/release/
├─ SKILL.md
├─ scripts/
└─ references/

SKILL.mdに起動条件、手順、完了条件をまとめ、必要なタスクで再利用する。

Skillは「仕事の進め方」を一つの配布単位にする。

MULTI-AGENT ROLE

config.tomlの[agents]

[agents.reviewer]
description = "変更をレビューする"
config_file = "agents/reviewer.toml"
  • 役割はdescription、個別設定はconfig_fileで結び付ける。
  • 同時実行上限はmax_concurrent_threads_per_sessionで設定する。
  • 固定の並列数は前提にせず、環境と作業に合わせて決める。
CODEX · 04

実行境界はconfig.tomlで定める

サンドボックス・承認・MCP・inline hooksを、指示文書から切り離して管理する

CONFIGURATION SURFACE

sandbox_mode

ファイルやコマンドが触れられる範囲を指定する。

approval_policy

操作前に承認を求める条件を定める。

mcp_servers

外部ツールやデータソースへの接続を設定する。

inline hooks

実行フローへ組み込む自動処理をconfig.toml内で定義する。

[agents]

エージェント役割と個別設定ファイルの対応を宣言する。

AGENTS.mdは権限設定ではない

AGENTS.mdは作業指示を伝える。実行可能範囲と承認条件はconfig.tomlの制御キーで決める。

プロジェクト文脈・rules・skills・agents・実行設定を、Cursor固有の配置へ分ける

資産正規配置AIへの効果
プロジェクト文脈AGENTS.mdリポジトリ全体の前提を共有する
プロジェクトrules.cursor/rules/*.mdcmetadataに応じて規約を適用する
再利用手順.cursor/skills/ または .agents/skills/作業手順を再利用可能な単位にする
カスタムagents.cursor/agents/*.md専門役割へタスクを委任する
実行境界.cursor/mcp.json / .cursor/cli.jsonMCP接続とCLI権限をそれぞれ制御する
CURSOR · 02

AGENTS.mdとMDC rulesを分ける

ルートの共通文脈は平文Markdown、適用条件付き規約は.mdc metadataで管理する

ROOT CONTEXT

AGENTS.md

リポジトリのルートへ置くプレーンMarkdown。技術構成、用語、共通コマンドなどをまとめる。

frontmatter不要：
ファイル自体は平文Markdownとして扱い、プロジェクト全体の入口にする。

PROJECT RULE

.cursor/rules/*.mdc

rule本文とmetadataを同じ.mdcファイルに持たせる。

globs
対象ファイルのパターンを指定する。
alwaysApply
常時適用するruleかどうかを明示する。
description
ruleの目的を説明し、適用判断の手掛かりにする。
色やファイル名ではなく、metadataの条件がruleの読まれ方を決める。
CURSOR · 03

skillsは手順、agentsは専門役割

繰り返すワークフローと、別コンテキストへ委任する役割を別資産にする

REUSABLE WORKFLOW

Skills

.cursor/skills/release/
└─ SKILL.md

.agents/skills/review/
└─ SKILL.md

プロジェクト事情に合わせ、どちらかのskills配置で起動条件と実行手順を管理する。

Skillは「同じ作業をどう再現するか」を定義する。

CUSTOM AGENT

.cursor/agents/*.md

.cursor/agents/reviewer.md
役割の説明
利用するモデルや設定

レビュー、調査、実装などの専門役割を定義し、必要なタスクを委任する。

  • 固定の並列数は前提にしない。
  • Skillの手順とagentの責務を重複させない。
CURSOR · 04

MCP接続とCLI権限を分けて置く

プロジェクトMCPはmcp.json、Cursor CLIのpermissionsはcli.jsonで管理する

EXECUTION CONTROLS

.cursor/mcp.json

プロジェクトで利用するMCPサーバーと接続情報を定義する。

.cursor/cli.json

Cursor CLIでのコマンド実行permissionsを管理する。

.cursor/rules/*.mdc

実行権限ではなく、AIが守るプロジェクトruleを定義する。

AGENTS.md

実行権限ではなく、リポジトリ全体の文脈と作業指示を伝える。

permissions.jsonを万能扱いしない

Cursor CLIの権限制御は.cursor/cli.json。MCP接続は.cursor/mcp.jsonであり、目的ごとに設定面を分ける。

CLAUDE CODE 環境構築

複数アカウントを設定ディレクトリで隔離する

CLAUDE_CONFIG_DIRで構成・起動・Bedrock認証・モデル制約を分けて確認する

01 / 原理

設定ディレクトリを分ければ、2つのアカウントを並行利用できる

CLAUDE_CONFIG_DIRが参照先を切り替え、認証・設定・規約・履歴を互いに隔離する。

メインアカウント

~/.claude/

  • 認証認証情報
  • 設定settings.json
  • 規約・手順rules / skills
  • 作業履歴セッション履歴

デスクトップアプリ・VS Code・CLIが参照

サブアカウント

~/.claude-account-b/

  • 認証認証情報
  • 設定settings.json
  • 規約・手順rules / skills
  • 作業履歴セッション履歴

CLI専用。環境変数で参照先を切り替える

02 / 運用

サブ環境は起動時に指定し、日常利用はaliasへ短縮する

対応範囲はCLIに限定される。デスクトップアプリとVS Codeでは切り替えられない。

起動コマンド

CLAUDE_CONFIG_DIR=~/.claude-account-b claude

~/.zshrcに追記するalias

alias claude-account-b='CLAUDE_CONFIG_DIR="$HOME/.claude-account-b" claude'

登録後はclaude-account-bで起動できる。

対応範囲

  • CLI
    CLAUDE_CONFIG_DIRによる切り替えに対応
  • デスクトップアプリ・VS Codeは非対応
  • Bedrock接続はサブ環境のsettings.jsonで設定する
03 / 認証

Bedrockサブ環境は認証方式に合わせてenvを選ぶ

例示の識別名・リージョン・秘密値は実値ではない。実環境の値へ置き換える。

命名例: ~/.claude-bedrock-{識別名}/
作成例: mkdir -p ~/.claude-bedrock-dev

~/.claude-bedrock-{id}/settings.jsonのenvへ、CLAUDE_CODE_USE_BEDROCKとAWS_REGIONを必ず含める。

認証方式判別・事前条件settings.jsonのenv例（秘密値はプレースホルダー）
Bearer Token AccessKeyが
{user}-at-{accountId}形式		 "CLAUDE_CODE_USE_BEDROCK": "1", "AWS_REGION": "ap-northeast-1", "AWS_BEARER_TOKEN_BEDROCK": "ABSK..."
IAMアクセスキー AccessKeyが
AKIA...で始まる		 "CLAUDE_CODE_USE_BEDROCK": "1", "AWS_REGION": "ap-northeast-1", "AWS_ACCESS_KEY_ID": "AKIA...", "AWS_SECRET_ACCESS_KEY": "..."
SSO / Identity Center 事前に
aws sso login --profile {profile}		 "CLAUDE_CODE_USE_BEDROCK": "1", "AWS_REGION": "ap-northeast-1", "AWS_PROFILE": "my-sso-profile"

確認方法: /statusで「Provider: Amazon Bedrock」と表示されることを確認する。

04 / 制約

Bedrockではリージョン別モデルIDを固定し、利用制約を確認する

モデルID例は設定形式を示す例であり、実環境で利用可能なモデルを確認して指定する。

settings.jsonのenvへモデルIDを追加

BedrockのデフォルトモデルはAnthropic APIより遅延する。リージョンプレフィックス付きモデルIDを追加して固定する。

例: jp.anthropic.claude-opus-4-8

実行上の制約

WebSearchツールは利用不可。

リージョンとプレフィックスの対応

us-east-1
us.anthropic.
ap-northeast-1
jp.anthropic.
eu-west-1
eu.anthropic.

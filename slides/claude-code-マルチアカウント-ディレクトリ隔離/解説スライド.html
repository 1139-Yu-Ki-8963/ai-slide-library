Claude Code 環境構築 — 運用

サブ環境は起動時に指定し、日常利用はaliasへ短縮する

切り替えに対応するのはCLIのみ — デスクトップアプリとVS Codeは既定環境で動く

起動コマンド

CLAUDE_CONFIG_DIR=~/.claude-account-b claude

~/.zshrc に追記するalias

alias claude-account-b='CLAUDE_CONFIG_DIR="$HOME/.claude-account-b" claude'

登録後は claude-account-b の1語でサブ環境を起動できる。

対応範囲

  • CLICLAUDE_CONFIG_DIRによる切り替えに対応する
  • デスクトップアプリ・VS Code非対応。常に既定の ~/.claude/ を参照する
  • Bedrock接続サブ環境の settings.json で設定する（次ページ）
運用の原則 サブ環境はCLI限定 — GUIから使う作業はメインアカウント側に寄せる 2 / 4
Claude Code 環境構築 — Bedrock認証

Bedrockサブ環境は、認証方式に合わせてenvを選ぶ

settings.json のenvに CLAUDE_CODE_USE_BEDROCK と AWS_REGION を含める（値は例示）

認証方式 判別・事前条件 settings.json のenv例
Bearer Token AccessKeyが{user}-at-{accountId}形式
"CLAUDE_CODE_USE_BEDROCK": "1", "AWS_REGION": "ap-northeast-1", "AWS_BEARER_TOKEN_BEDROCK": "ABSK..."
IAMアクセスキー AccessKeyがAKIA...で始まる
"CLAUDE_CODE_USE_BEDROCK": "1", "AWS_REGION": "ap-northeast-1", "AWS_ACCESS_KEY_ID": "AKIA...", "AWS_SECRET_ACCESS_KEY": "..."
SSO / Identity Center 事前にaws sso login --profile {p}
"CLAUDE_CODE_USE_BEDROCK": "1", "AWS_REGION": "ap-northeast-1", "AWS_PROFILE": "my-sso-profile"
確認方法 /status で「Provider: Amazon Bedrock」と表示されれば接続完了 3 / 4
Claude Code 環境構築 — モデル制約

Bedrockではリージョン別モデルIDを固定し、制約を確認する

モデルID例は形式の例示 — 実環境で利用可能なモデルを確認して指定する

settings.json のenvへモデルIDを追加する

Bedrockの既定モデルはAnthropic APIより遅延することがある。リージョンプレフィックス付きモデルIDを指定して固定する。

"ANTHROPIC_MODEL": "jp.anthropic.claude-opus-4-8"

実行上の制約　WebSearchツールは利用不可。

リージョンとプレフィックスの対応

us-east-1
us.anthropic.
ap-northeast-1
jp.anthropic.
eu-west-1
eu.anthropic.
制約の要点 モデルIDはリージョンに合わせて固定する — 既定のままでは速度も挙動も安定しない 4 / 4

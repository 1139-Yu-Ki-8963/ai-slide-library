AI 採用 成熟度モデル

AI 採用の 5 段階で、機能とガードレールを同時に整える

使える機能が増えるほど、権限・監視・自動検証を段階的に強化する

1 導入基盤を作る
2 並列で動かす
3 自律に委ねる
LEVEL 1

利用制限
Gated

使う機能

—（AI 未導入）

必要な整備
  • SSO/SCIM + 役割ベースアクセス制御
  • 組織レベルの予算上限
  • 既存承認フローへの組込み

→ 経営層と合意し導入枠組みを構築

LEVEL 2

1対1ペア作業
Assisted

使う機能
  • Claude Code（CLI / IDE）
  • Cowork / Design
  • 利用状況ダッシュボード
必要な整備
  • 個人ごとの利用上限
  • モデル設定の中央管理
  • 利用ログを既存監視へ連携

→ 複数エージェント運用と自己検証ループの確立

LEVEL 3

並列オーケストレーター
Parallel

使う機能
  • Auto mode / Agent view
  • コード・セキュリティレビュー
  • Worktree isolation
必要な整備
  • 自動レビューとE2E検証
  • 安全なコマンドの事前承認
LEVEL 4

監督付き自律
Supervised

使う機能
  • Subagents + Worktree
  • Dynamic workflows / Routines
  • 使用状況モニタリング
必要な整備
  • 自動レビューとAgent sandbox
  • CLAUDE.md の整備
  • モデル選択とトークン制御
LEVEL 5

AI ネイティブ
AI-native

使う機能
  • Claude Agent SDK
  • Slack からの自動起動
必要な整備
  • 自動化のコスト制御
  • 自動化のモデル選択
!

よくある失敗: ガードレールなしに Level 3 の並列運用に飛びつく → 自動レビューがないまま出力が溢れ、品質が崩壊する

1

導入基盤を作る（Level 1〜2）— 承認の壁を取り、1対1ペアで信頼を築く

2

並列で動かす（Level 3）— Auto mode と自動レビューで 5〜10 エージェントを同時運用

3

自律に委ねる（Level 4〜5）— AI 主導で書き、人間は意図と例外に集中

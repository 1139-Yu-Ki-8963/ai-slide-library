Claude Code｜リポジトリ整備の現状・理想・差分

AIが自走するには「読める文書」と「見える仕組み」を揃える — 不足と整備すべき配置を対比する

資産 現状 理想の配置 差分（次に行うこと）
プロジェクト
説明書		 未作成技術構成・コマンド・守るべき原則をAIに伝えられない CLAUDE.mdプロジェクトの索引兼行動原則。セッション開始時に自動で読み込まれる 技術構成・コマンド一覧・行動原則を1ファイルに整理して配置
設計書 0件機能仕様が口頭やSlackに散在し、AIは実装意図を推測する docs/機能・画面の設計書を格納し、AIが仕様を参照できる 主要機能の設計書を作成し、体系的に配置
規約ファイル 0件命名・コーディング規約が暗黙知で、AIの書き方が揺れる rules/規約をMarkdownで記述し、編集対象に必要な規約だけをAIへ渡す 命名規則・コーディング規約をファイル種別ごとに整理
作業手順書 未整備繰り返し作業が属人化し、人が毎回口頭で指示している skills/定型作業を構造化し、名前で呼ぶだけでAIが手順どおりに動く 頻出の作業パターンを再利用可能な手順書に整理
可視化サイト なし規約・画面・APIを人が全体で俯瞰する手段がない project-portal/規約・画面・マスタ表をブラウザで読めるサイトとして構築する 規約・画面・APIの索引を、人とAIの共通参照点に
整備順 説明書 → 設計書 → 規約 → 手順書 → 可視化 — 依存関係の上流から順に接続する 1 / 1

GAP ANALYSIS — CLAUDE CODE

Claude Code導入前の5つの欠落を診断する

説明書・設計書・規約・手順書・可視化サイトの不足が、AIの推測と属人運用を生む

AIが自走するには「読める文書」と「見える仕組み」をリポジトリに揃える

■現状の欠落・理想の配置先・整備アクションを、依存関係の上流から下流へ読む

対象リポジトリの現状診断（上流から下流の依存順）
カテゴリ 現状 理想 ギャップ
1 プロジェクト
説明書		 未作成 技術構成・コマンド・守るべき原則を AI に伝えられない CLAUDE.md プロジェクトの索引兼行動原則。AI が開始時に読む 技術構成・コマンド・原則を 1 ファイルに整理
2 設計書 0件 機能仕様が口頭や Slack に散在し、AI は実装意図を推測する docs/ 機能・画面の設計書を格納し、AI が仕様を参照できる 主要機能の設計書を作成し、体系的に配置
3 規約
ファイル		 0件 命名・コーディング規約が暗黙知で、AI の書き方が揺れる rules/ 規約を Markdown 化し、編集対象に必要な規約だけを AI へ渡す 命名・コーディング規約をファイル種別ごとに文書化
4 作業
手順書		 未整備 繰り返し作業が属人化し、人が毎回口頭で指示している skills/ 定型作業を構造化し、名前で呼ぶだけで AI が手順どおりに動く 頻出作業を洗い出し、再利用可能な手順書に整理
5 可視化
サイト		 なし 規約・画面・API を人が全体で俯瞰する手段がない project-portal/ 規約・画面・マスタ表をブラウザで読めるサイトとして構築 規約・画面・API の索引を HTML 化し、人と AI の共通参照点にする
